Context Monitoring

The monitor tracks your session health in real time and tells you when quality is degrading — before compaction forces your hand.

The Three Context Zones

The monitor classifies every session into one of three zones based on token consumption and recall quality metrics:

Healthy — Token consumption is within normal range. Performance is near the warm-up baseline. No action needed.

Degrading — Multi-needle recall is dropping. Claude's responses are becoming less context-specific. This is the right time to save — you still have good context to preserve.

Critical — Compaction is imminent. Save immediately. Waiting risks losing context without a named checkpoint.

Note

The Degrading zone is where saving has the highest value. At Critical, the context is already partially compromised. Don't wait for Critical to act.

The Status Line

The monitor writes a status line to Claude Code's UI on every message. Format:

◐ Degrading | 87k / 200k tokens (43%) | ~18 min | $0.34
FieldMeaning
Zone indicator● Healthy, ◐ Degrading, ● Critical (color-coded)
Token countCurrent tokens used / context window size
PercentageFill level as a percentage of the window
Time estimateEstimated time until compaction at current burn rate
Session costAccumulated API cost for this session

Warm-Up Baseline

The monitor calibrates against a warm-up baseline — a measurement of context quality at the start of a session, before deep work has accumulated. This baseline is used to detect when quality is declining relative to the session's peak.

The baseline is set automatically when you start a session or resume a context. You can reset it manually if the session scope changes significantly:

/monitor reset-baseline

Zone Warnings

When the session transitions from Healthy to Degrading, or from Degrading to Critical, the monitor emits a zone warning inline:

⚠ Context zone: DEGRADING
   87k tokens used (43%). Recall quality declining.
   Recommend: /context-save before continuing.
⛔ Context zone: CRITICAL
   162k tokens used (81%). Compaction imminent.
   Save now: /context-save <name>

Warnings fire once per zone transition. If you save and resume, the zone resets.

Burn Rate and Cost Estimation

The monitor tracks how quickly tokens are consumed per message (burn rate). Using the burn rate and remaining token budget, it estimates time to compaction. This estimate is shown in the status line as ~18 min.

Cost is accumulated from session start using Anthropic's published pricing for the active model. The monitor does not make API calls to track cost — it calculates locally from token counts and model rates stored in monitor-config.json.

Monitor Configuration

The monitor reads configuration from ~/.claude/context-curator/monitor-config.json:

{
  "degradingThreshold": 0.40,
  "criticalThreshold": 0.75,
  "burnRateWindow": 10,
  "modelRates": {
    "claude-opus-4-7": { "input": 15.00, "output": 75.00 },
    "claude-sonnet-4-6": { "input": 3.00, "output": 15.00 }
  }
}

degradingThreshold and criticalThreshold are fractions of the context window (0.40 = 40%). burnRateWindow is the number of recent messages used to calculate the rolling burn rate average.

How the Monitor Works

The monitor runs as a PostMessage hook — it fires after every Claude response, reads the current token count from the session state, calculates zone and metrics, and updates the status line. No model API calls are made. All computation is local arithmetic over token counts and timestamps.

This means monitoring has no cost and no latency impact on your session.
